## 구현 메모
- 변경한 파일: `functions/src/reviewNotifications.ts`, 검수 응답·자동 완료·예약 함수, 웹 알림 센터·헤더, Firestore 규칙·인덱스, 에뮬레이터·브라우저 검증, 관련 문서.
- 의사결정 및 이유: 제출·재제출과 완료 알림은 업무 상태 전이와 같은 트랜잭션에서 작성한다. 8/2근무시간 알림은 기존 1분 주기 작업이 현재 검수 회차와 기한을 다시 확인한 뒤 생성한다. 업무·회차·종류·수신자 기반 고정 ID로 재실행 중복을 막는다. 알림 센터는 현재 워크스페이스의 본인 알림 최근 50개를 실시간으로 표시한다.
- 발견한 문제/해결: 이전 회차의 리마인드나 완료·반려 뒤 알림이 재발송되지 않도록 상태·회차·제출 시각·기한을 재검증한다. 수신자라도 멤버십을 잃으면 알림 읽기와 읽음 처리를 거부한다. 브라우저 테스트는 읽음 함수 완료까지 기다리도록 수정했다.
- 다음 일차에 넘길 사항: 실제 Firebase 프로젝트의 Functions·Firestore 인덱스·규칙 배포와 운영 확인은 별도로 필요하다. 앱 내부 알림만 구현했으며 이메일·브라우저 푸시는 범위 밖이다.

## 포트폴리오 기록
- 문제 정의: 검수 요청과 마감 임박·완료 상태를 업무 보드에 들어가야만 알 수 있었고, 중복 예약 실행은 같은 알림을 여러 번 만들 수 있었다.
- 선택한 접근과 대안: 현재 업무 상태를 서버에서 확인하고 알림 문서를 원자적으로 생성한다. 별도 메일·푸시 대신 접근 권한을 가진 사용자에게 실시간 앱 내부 알림 센터를 제공한다.
- 검증 근거(수치 임의 생성 금지): Firestore 에뮬레이터에서 제출·8/2근무시간·완료·회차별 중복 방지·수신자와 탈퇴 멤버 권한을 확인했다. 두 Chrome 세션 통합 검증에서 요청자와 담당자의 알림 표시·읽음 처리·업무 보드 이동을 확인했다. Functions·웹 타입 검사와 웹 린트가 통과했다.
