# 41일차 — 유형별 워크스페이스

- 이전: [40일차](day-40.md) / 다음: [42일차](day-42.md)
- 상태: 완료 (2026-11-27, 로컬 구현·검증)
- 근거: [현재 코드와 Talkgo 기획 차이](../11-talkgo-expansion.md)

## 작업

- workspaceApi·WorkspaceGate·Functions에 유형 저장과 기존 공간 기본 work 처리.
- 기존 업무용 동작·데이터 접근 범위를 확인하며 해당 기능의 서버 검증과 화면 상태를 함께 갱신한다.

## 완료 기준

- 한 계정이 업무·모임 공간을 각각 만들고 전환 가능.
- 관련 권한·오류·재시도 경로를 검증하고 결과를 이 문서에 기록한다.

## 구현 결과

- 새 워크스페이스 생성 화면과 기존 공간의 전환 메뉴에서 `업무 공간(work)`·`모임 공간(meetup)`을 선택한다. 공간이 없는 계정과 기존 공간의 멤버 모두 새 공간을 만들 수 있다. 유형은 `workspaces/{id}.type`에 저장하며 사용자별 공간 목록에는 복제하지 않는다.
- 유형이 없는 기존 문서만 `work`로 읽는다. `null`, 빈 문자열, 미지원 값은 오류로 표시하고 재시도·다른 공간 전환 경로를 제공한다. 생성 후 유형 변경은 Firestore Rules에서 거부한다. 기존 3필드 생성도 호환 기간 동안 허용한다.
- 모임 공간에서는 업무 보드·캘린더·메시지의 업무 요청 버튼·업무 알림을 숨긴다. Functions의 업무 생성·AI 제목 제안·기존 업무용 회의 생성도 원본 공간 유형을 확인해 `meetup`과 미지원 유형을 거부한다. 모임 전용 홈과 제안·투표 기능은 이후 일차에 구현한다.

## 검증

- `npm run test:workspace`: 새 두 유형 생성, 레거시 생성, 잘못된 유형 및 유형 변경 거부, 기존 초대·권한 흐름 통과.
- `npm run test:task-model`, `npm run test:meeting`: 레거시·명시적 업무 공간은 생성 가능, 모임·잘못된 유형은 거부됨.
- `npm run test:workspace-types`: 실제 브라우저에서 동일 계정의 두 유형 생성·전환, 레거시 표시, 잘못된 유형 오류·재시도·다른 공간 복귀 통과.
- `npm run typecheck`, `npm run lint`, `npm run test:ui`, `npm run build:web` 통과.

운영에는 아직 배포하지 않았다. 배포할 때는 [이전 설계](../12-talkgo-schema-migration.md)의 기준선과 백업을 확인하고, 호환 읽기·서버 검증과 Rules를 먼저 적용한 뒤 새 생성 화면을 제공해야 한다. 기존 문서 백필은 실행하지 않았다.
