## 구현 메모
- 변경한 파일: `functions/src/reviewTimeout.ts`, `functions/src/index.ts`, `functions/src/taskResponses.ts`, `firestore.indexes.json`, 로컬 반복 실행 스크립트, 웹 업무 보드·계약 타입, 에뮬레이터 검증·브라우저 테스트 시나리오, 관련 문서.
- 의사결정 및 이유: 배포 환경에서는 1분 간격 Cloud Scheduler 함수가 검수 기한이 지난 업무를 조회한다. `dev:all`에서는 같은 서버 로직을 로컬 반복 실행기로 호출한다. 상태·회차·제출 시각·기한을 트랜잭션 안에서 다시 확인한 뒤 `DONE`과 자동 완료 이력을 함께 기록한다. 기한이 지난 요청자의 승인·반려도 거부해 예약 실행 전의 틈을 막는다.
- 발견한 문제/해결: 예약 함수는 중복되거나 겹쳐 실행될 수 있다. 이전 회차 후보와 동시 승인·반려가 중복 완료하지 않도록 트랜잭션의 현재 문서 상태를 확인한다. 처리 실패는 다음 예약 실행에서 재시도한다. 두 브라우저 통합 검증은 로컬 JVM 메모리 부족으로 에뮬레이터가 종료되어 완료하지 못했다.
- 다음 일차에 넘길 사항: 자동 완료·검수 리마인드 알림은 26일차에 연결한다. 실제 Firebase 프로젝트의 예약 함수 배포 및 운영 확인은 별도로 필요하다.

## 포트폴리오 기록
- 문제 정의: 저장된 검수 기한이 지나도 업무가 `REVIEW_PENDING`에 남고 요청자 응답과 자동 완료가 충돌할 수 있었다.
- 선택한 접근과 대안: 매 업무마다 별도 타이머를 저장하는 대신 기한 인덱스를 조회하는 1분 주기 작업을 사용했다. 회차 토큰과 트랜잭션으로 오래된 작업 및 중복 실행을 차단했다.
- 검증 근거(수치 임의 생성 금지): Firestore 에뮬레이터에서 기한 전후, 중복 실행, 재제출 회차, 기한 후 승인·반려 차단과 동시 경합을 확인했다. Functions·웹 빌드와 웹 타입 검사가 통과했다. 두 브라우저 통합 검증은 로컬 시스템 자원 부족으로 미완료 상태이며 테스트 시나리오만 추가했다.
