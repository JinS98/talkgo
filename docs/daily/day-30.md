## 구현 메모
- 변경한 파일: `apps/web/src/features/tasks/TaskCalendarPanel.tsx`, `TaskCalendarPanel.module.scss`, `calendarEvents.ts`, 캘린더 단위·브라우저 검증 스크립트, `README.md`.
- 의사결정 및 이유: 담당자가 업무 바를 옮기거나 마감 쪽 끝을 늘리면 FullCalendar의 변경을 즉시 되돌리고 제안 확인 창을 연다. 원래 마감의 시각은 유지하고 이동한 서울 날짜만 적용한다. 제안·승인·거절은 기존 `respondTask` 서버 트랜잭션을 재사용한다.
- 발견한 문제/해결: 드래그가 곧바로 확정된 것처럼 보이지 않도록 `revert()` 후 제안 창을 연다. 검수·회의, 완료된 업무, 담당자가 아닌 사용자, 제안 대기 중인 업무는 드래그를 허용하지 않는다.
- 다음 일차에 넘길 사항: 31일차 업무↔원본 메시지·DM 이동과 권한 점검.

## 포트폴리오 기록
- 문제 정의: 캘린더에서 마감을 움직여도 실제 업무 마감 변경 절차와 연결되지 않았다.
- 선택한 접근과 대안: 캘린더 조작은 새 날짜의 초안만 만들고, 담당자 제안과 요청자 승인을 별도 서버 호출로 처리했다. 요청자에게는 캘린더 안의 제안 목록과 승인·거절 버튼을 제공했다.
- 검증 근거(수치 임의 생성 금지): `npm run build:web`, `npm run lint`, `npm run test:calendar` 통과. Auth·Firestore·Functions 에뮬레이터와 Chrome의 `verify:calendar-browser`에서 드래그 직후·제안 후 기존 마감 유지, 요청자 승인 후 변경, 거절 후 마감 유지까지 확인했다.
