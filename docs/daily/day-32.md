## 구현 메모
- 변경한 파일: `apps/web/scripts/verify-workspace.mjs`, `docs/daily/day-32.md`, `README.md`.
- 의사결정 및 이유: 기존 초대·소켓·업무 테스트를 보안 체크리스트로 재실행하고, 초대 수락/철회 경합·DM 목록 쿼리·멤버십 제거 후 접근·목록 응답의 토큰 비노출을 추가했다. 서버 규칙과 화면 권한을 각각 확인하기 위해 테스트를 구분했다.
- 발견한 문제/해결: 공개 업무와 비공개 DM의 권한 경계는 메시지 문서뿐 아니라 목록 쿼리와 업무→원본 이동에도 적용되어야 한다. 해당 경로를 테스트에서 확인했다.
- 다음 일차에 넘길 사항: 33일차 UX·성능 점검. 실제 프로젝트 배포 후 규칙과 Functions의 배포 상태를 별도로 확인할 것.

## 포트폴리오 기록
- 문제 정의: 초대 토큰, 멤버십, 소켓 룸, 업무 원본이 서로 다른 계층에서 처리되어 단일 화면 테스트만으로 권한 경계를 확인하기 어렵다.
- 선택한 접근과 대안: Firebase Auth·Firestore·Functions 에뮬레이터와 소켓 테스트에서 허용/거부·동시 요청·권한 변경 직후를 검증하고, 원본 이동은 별도 브라우저 테스트 결과와 연결했다.
- 검증 근거(수치 임의 생성 금지): 위 명령의 성공 종료와 각 테스트의 통과 출력. 테스트에 실제 초대 토큰이나 DM 본문을 결과 문서에 기록하지 않았다.
