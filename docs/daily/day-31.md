## 구현 메모
- 변경한 파일: `App.tsx`, 채팅·업무 보드 화면 및 스타일, 내비게이션 상태, 채팅 기록 훅, 31일차 전용 브라우저 테스트, README.
- 의사결정 및 이유: 업무는 워크스페이스 공개 상태를 유지한다. 원본 메시지는 이동할 때 Firestore 서버에서 다시 조회해 현재 채널·DM 읽기 권한을 확인한다. 원본 본문과 DM 방 정보는 업무 문서에 복제하지 않는다.
- 발견한 문제/해결: 오래된 원본 메시지를 화면에 넣으면 채팅 기록 갱신이 해당 메시지까지 모든 페이지를 읽을 수 있어, 원본으로 이동한 경우 최근 페이지와 해당 메시지만 불러오도록 했다. 전체 채팅 시나리오는 기존 초대 대기·캘린더 단계에서 간헐적으로 실패해 링크 기능 전용 브라우저 검증을 분리했다.

## 포트폴리오 기록
- 문제 정의: 업무 카드와 원본 대화가 분리되어 맥락을 확인하려면 직접 채널·DM을 찾아야 했다. DM 원본은 비참여자에게 노출되지 않아야 한다.
- 선택한 접근과 대안: 메시지에는 연결된 업무 버튼을, 카드에는 원본 대화 버튼을 두고 화면 내에서 대상 항목을 강조했다. 원본을 업무 문서에 저장하는 방식은 비참여자에게 DM 내용이 공개될 수 있어 사용하지 않았다.
- 검증 근거(수치 임의 생성 금지): `npm run build:web`, `npm run lint -w @taskgo/web`, `npm run test:task-links` 통과. Firebase 에뮬레이터 브라우저에서 채널·DM 왕복 이동, 오래된 원본 메시지 표시, DM 비참여자의 원본 접근 거부를 확인했다.
