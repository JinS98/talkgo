# 35일차 — 최종 검증·문서

- **현재 상태: 운영 핵심 흐름 검증 완료 (외부 연동 설정 대기)**

## 목표

2브라우저 운영 시연, 비용 설정 확인, README·포트폴리오·회고 완성.

## 완료한 작업

- 운영 Firebase Auth에 임시 이메일 계정 2개를 만들고 분리된 Chrome 브라우저 컨텍스트에서 로그인했다. 테스트 전용 워크스페이스·멤버십을 구성했다.
- 두 브라우저에서 Cloud Run 실시간 연결, 채널 메시지 수신, 메시지→업무 요청, 담당자 수락과 보드 동기화, 캘린더 일정, 팀원 프로필→DM 생성과 개인 메시지 수신을 확인했다.
- 390px 모바일 화면에서 뷰포트 가로 넘침이 없고, 두 브라우저의 JavaScript 페이지 오류가 없음을 확인했다.
- [시연 화면 4장](../10-portfolio.md#주요-화면)을 저장하고 [README](../../README.md)에서 운영 데모와 포트폴리오로 연결했다.
- 검증 후 임시 Auth 계정 **2개**, 테스트 Firestore 문서 **13개**를 삭제했다. 테스트에서 실제 초대 메일 대신 전용 멤버십을 등록했다.
- `npm run typecheck`, `npm run lint`가 통과했다.

## 운영 검증 범위

| 항목 | 결과 |

| 채널·DM의 2브라우저 실시간 메시지 수신 | 통과 |
| Cloud Functions `createDm`, `createTask`, `respondTask` 호출 | 통과 |
| 업무 요청·수락 후 보드와 캘린더 반영 | 통과 |
| 모바일 390px 가로 넘침, 브라우저 페이지 오류 | 넘침 없음, 오류 없음 |
| 실제 초대 메일 수신·수락 | 미검증: SMTP 설정 대기 |

| OpenAI 제목 초안 | 미검증: API 키 설정 대기 |

초기 DM 검증에서는 방 전환이 완료되기 전에 테스트가 메시지를 입력해 이전 채널에 저장했다. DM 선택과 연결 완료를 기다리도록 시연 순서를 수정했고 재검증에서 상대 브라우저 수신까지 통과했다. 앱 코드 오류는 발견하지 않았다.

## 비용 확인

- 청구 계정 연결 활성화와 Taskgo 프로젝트만 포함하는 월 **5,000원** 예산을 재확인했다. 실제 지출 10%·50%·100% 알림이 설정되어 있다.
- Cloud Run 소켓 서비스는 준비 상태이고 서비스 전체 최대 인스턴스가 1이다. 최소 인스턴스는 0으로 배포했다.
- `completeExpiredReviews` Cloud Scheduler 작업은 **1분 간격, ENABLED**다. 사용량에 따라 비용이 발생할 수 있으므로 운영 시 관찰해야 한다.
- **실제 청구액은 이 검증에서 확인하지 못했다.** 예산 알림은 과금을 막지 않으며 사용량 반영 후 Google Cloud 결제 보고서에서 확인해야 한다.

## 남은 설정

- SMTP 서비스·발신 주소를 결정하고 `INVITE_SMTP_URL`, `INVITE_FROM`을 설정한 뒤 초대 메일 수신·수락을 실제 주소로 검증한다.
- OpenAI API 키를 설정한 뒤 명시적 클릭의 초안 제안과 오류·비용을 검증한다.
- Google 로그인, 동일 이메일 계정 연결·충돌, 실제 결제 보고서를 운영 계정에서 확인한다.
- 로컬 `test:workspace` 재실행 시 기본 Java 17은 지원되지 않아 JDK 21을 선택했다. 이어 8080 포트가 이미 실행 중인 `demo-taskgo` Firestore 에뮬레이터에 점유되어 별도 실행을 중단했다. 기존 실행 환경은 건드리지 않았고, 이번 검증의 핵심 흐름은 운영 두 브라우저에서 확인했다.

## 회고

- 실시간 기능은 서버 상태만으로 검증할 수 없었다. 실제 계정 두 개로 채널·DM의 수신과 업무 데이터의 화면 간 반영을 확인한 것이 가장 유효했다.
- 비동기 DM 생성 뒤 방 전환 완료를 기다리지 않으면 테스트가 이전 채널에 전송할 수 있었다. 시연 단계마다 선택한 방과 연결 상태를 확인하도록 고쳤다.
- 배포 성공과 외부 연동 완료는 별개다. SMTP·OpenAI 키와 실제 청구액처럼 추가 입력이나 시간이 필요한 항목은 검증 결과에서 분리해 기록했다.

## 포트폴리오 기록

- 문제 정의: 기능 구현 완료 후 실제 배포 환경에서 서로 다른 사용자의 대화·업무 흐름이 이어지는지 증명해야 했다.
- 선택한 접근: 테스트 전용 계정과 워크스페이스를 격리해 운영 환경에서 시연하고, 검증 직후 계정·문서를 정리했다.
- 검증 근거: 두 브라우저 시나리오 통과, 화면 캡처 4장, 타입 검사·린트 결과, Google Cloud 배포·예산·Scheduler 설정 조회. 외부 연동과 실제 청구액은 검증 범위 밖으로 명시했다.
