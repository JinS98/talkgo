## 작업

- `workspaces.type`의 누락은 기존 업무 공간으로 읽고, 명시적 미지원 유형은 오류로 처리하는 호환 규칙을 정했다. `users/{uid}/workspaces`는 탐색용 복사본이고 유형·권한의 원본은 `workspaces`와 현재 멤버십이다.
- 기존 `tasks`, `taskEvents`, `meetings`, 채팅·초대 문서는 유지한다. 기존 `meetings`는 업무용 회의이며 새 모임 이벤트로 일괄 변환하지 않는다.
- 모임 제안·버전별 투표·확정 이벤트·반복 시리즈의 경로와 필수 필드, 참석 대상별 읽기, 서버 전용 상태 전이, 중복 방지 ID를 설계했다.
- 필요한 복합 색인 후보를 실제 조회별로 정리하고, 쿼리·Rules 구현과 검증 전에는 미사용 색인을 배포하지 않기로 했다.
- 백업/내보내기, 호환 읽기, 양쪽 생성 형태 허용, 신규 쓰기, 조건부 백필, 무손실 대조, 모임 기능 개방, 롤백 순서를 기록했다. Firestore 관리형 내보내기는 일관된 시점 스냅샷이 아니므로 기준선 보존 방법을 별도로 구분했다.

## 완료 기준

- 유형 없는 기존 공간을 `work`로 읽는 호환·백필·롤백 절차를 문서화했다. 유형별 Rules는 40일차, 저장·화면 분기는 41일차 구현 범위다.
- 새 모임 컬렉션·색인·Rules·백필은 아직 코드나 운영 데이터에 적용하지 않았다. 설계 검증을 구현 완료로 오인하지 않도록 구분했다.

## 기존 기능 확인

| 검증 | 결과 |
| --- | --- |
| `npm run test:workspace` (JDK 21, 로컬 Emulator) | 통과: 공간 생성·초대 상태/경합·DM 쿼리·회의/업무 읽기·멤버십 철회 차단 |
| `npm run test:task-model` (JDK 21, 로컬 Emulator) | 통과: 요청자·담당자 권한과 업무 상태·검수·이력 |
| `npm run test:meeting` | 통과: 회의 입력·멤버 권한·저장 필드 |
| `npm run test:ui` | 통과: 사이드바 탐색·뷰 전환·대화 선택 |

권한 오류와 초대 재시도 경로는 37일차 서버·화면 수정 상태를 유지한다. 아직 없는 모임 문서의 권한/경합은 에뮬레이터에서 검증했다고 주장하지 않는다. 실제 백필과 운영 데이터 쓰기는 이번 일차에 하지 않았다.
