## 구현 메모
- 변경한 파일: `functions/src/reviewDeadline.ts`, `functions/src/taskResponses.ts`, `shared/contracts/src/task.ts`, 웹 업무 보드·캘린더, 계산·에뮬레이터·브라우저 검증 스크립트, 검수 정책·데이터 모델·README.
- 의사결정 및 이유: 서버에서 제출 시각부터 1근무일 8시간을 누적해 검수 기한을 계산한다. 서울 기준 평일 09~12시와 13~18시만 세고 주말·공휴일을 제외한다. 제출·재제출 시 기한과 회차별 이력을 같은 트랜잭션에 저장한다. 검수 대기 업무의 기한은 보드와 **내가 검수할 업무** 캘린더 필터에 표시한다.
- 발견한 문제/해결: `date-holidays`의 한국 달력에 2026년 이후 노동절·대체공휴일과 2026년 지방선거일이 없어 서버 규칙으로 보완했다. 새 임시공휴일·선거일이 확정되면 규칙과 검증 사례를 갱신해야 한다.
- 검증: `npm run test:review-deadline`의 점심·야간·주말·공휴일·대체공휴일·연도 경계 사례, Functions/웹 빌드·웹 린트, 로컬 Firebase 에뮬레이터의 제출·재제출·승인 흐름, 두 Chrome 계정의 보드·캘린더 표시를 확인했다.
- 다음 일차에 넘길 사항: 25일차 예약 자동 완료는 저장된 검수 기한·회차를 사용하고, 요청자 승인과 경합해도 결과가 하나만 남도록 처리한다.

## 포트폴리오 기록
- 문제 정의: 검수 기간을 선택해도 제출·재제출 업무에는 실제 기한이 없어서 담당자와 요청자가 언제까지 응답해야 하는지 확인할 수 없었다.
- 선택한 접근과 대안: 클라이언트 시계에 의존하지 않고 서버의 제출 시각과 오프라인 공휴일 규칙으로 계산했다. 시간 계산은 순수 함수로 분리해 점심·야간·연휴 경계를 검증했다.
- 검증 근거(수치 임의 생성 금지): 계산 사례 16개와 에뮬레이터의 중복 제출·재제출·승인 상태 검사, 두 브라우저에서 검수 기한 표시 및 검수 일정 바를 확인했다.
