# 42일차 — 유형별 홈·탐색

- 이전: [41일차](day-41.md) / 다음: [43일차](day-43.md)
- 상태: 완료 (2026-11-27, 로컬 구현·검증)
- 근거: [현재 코드와 Talkgo 기획 차이](../11-talkgo-expansion.md)

## 작업

- AppView와 WorkspaceLayout에 업무/모임 홈, 모바일 탐색 반영.
- 기존 업무용 동작·데이터 접근 범위를 확인하며 해당 기능의 서버 검증과 화면 상태를 함께 갱신한다.

## 완료 기준

- 업무 보드와 모임 제안 목록이 유형에 맞게 노출.
- 관련 권한·오류·재시도 경로를 검증하고 결과를 이 문서에 기록한다.

## 구현 결과

- 공간에 들어가거나 다른 공간으로 전환하면 유형별 홈을 연다. 업무 홈은 실제 업무 구독 결과로 요청 대기·진행·내 담당 건수와 진행할 업무를 표시하고, 각 업무를 보드에서 열 수 있다. 업무 조회 오류는 홈에서 재시도할 수 있다.
- 모임 홈에는 멤버·채널 수와 모임 제안 목록 진입 버튼을 배치했다. 모임 제안 목록은 별도 화면으로 열리며, 조회·응답 기능이 아직 준비 중임을 명확히 안내한다. 제안 데이터 계약·서버·Rules는 49일차 이후 작업이므로 가짜 제안이나 확정 일정을 표시하지 않는다.
- 탐색 레일은 업무 공간에서 홈·채팅·업무 보드·캘린더를, 모임 공간에서 홈·채팅·모임 제안을 보여 준다. 좁은 화면에서는 가로 스크롤로 모든 메뉴에 접근할 수 있다. 생성 안내가 모바일 공간 선택을 가리지 않도록 아래쪽에 배치했다.
- 새 공간 생성 직후 사용자별 목록의 로컬 갱신이 서버 커밋보다 먼저 도착할 수 있어, 유형의 서버 조회를 생성 완료 뒤에 실행한다. 유형은 불변이므로 원본 공간 문서를 일회성으로 읽고 오류 화면에서 다시 조회할 수 있다. 기본 채널 초기화는 선택한 홈 화면을 바꾸지 않는다.

## 검증

- `npm run test:ui`: 유형별 메뉴·홈·제안 화면, 실제 업무 요약과 오류 재시도 통과.
- `npm run test:workspace-types`: 로그인 브라우저에서 생성·전환·유형별 홈, 업무 보드·모임 제안, 레거시·이상 유형·재시도, 390px·320px 탐색과 가로 넘침 검증 통과.
- `npm run test:workspace`: 멤버 권한으로 원본 공간 유형을 읽는 규칙과 기존 초대·권한 회귀 검증.
- `npm run typecheck`, `npm run lint`, `npm run build:web` 통과.

운영에는 아직 배포하지 않았다. 모임 제안의 실제 목록·등록·투표는 데이터 모델과 서버 검증이 갖춰지는 이후 일차에 연결한다.
