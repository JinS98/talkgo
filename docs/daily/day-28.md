## 구현 메모
- 변경한 파일: `apps/web/src/features/tasks/TaskCalendarPanel.*`, `calendarEvents.ts`, `functions/src/meetingModel.ts`, `functions/src/index.ts`, 캘린더·회의 검증 스크립트와 관련 문서.
- 의사결정 및 이유: FullCalendar v7 월간 보드로 전환했다. 업무는 요청일~마감일, 검수 대기는 제출일~검수 기한으로 각각 표시한다. 회의는 시간 일정으로 표시하고 워크스페이스 멤버만 서버 함수로 생성한다. 팀 전체 필터에 회의를 포함하고 기존 내 담당·내 검수 필터를 유지한다.
- 발견한 문제/해결: FullCalendar의 종료일은 배타적이므로 서울 날짜로 변환한 마감일 다음 날을 업무·검수 바의 종료값으로 설정했다. 일정이 많은 날짜는 내장 더보기 팝오버를 사용한다.
- 다음 일차에 넘길 사항: 29일차 필터 정책 점검, 30일차 캘린더 드래그 시 마감 변경 제안 연결.

## 포트폴리오 기록
- 문제 정의: 기존 직접 구현한 월간 그리드는 업무 기간만 표시해 검수와 회의를 함께 볼 수 없었다.
- 선택한 접근과 대안: FullCalendar의 월간 이벤트·더보기 기능을 사용하고 일정 종류마다 색상과 테두리를 구분했다. 회의 생성은 클라이언트 직접 쓰기 대신 서버의 멤버 검증 트랜잭션을 사용했다.
- 검증 근거(수치 임의 생성 금지): `npm run build:web`, `npm run build:functions`, `npm run lint`, `npm run test:calendar`, `npm run test:meeting` 통과. Firebase 에뮬레이터와 Chrome을 사용한 `verify:calendar-browser`에서 요청 대기 업무 표시·일정 더보기·회의 등록·팀원에게 보이는지·필터를 확인했다. 전체 채팅 시나리오는 에뮬레이터 함수 초기 구동 지연으로 기존 업무 생성 단계에서 시간 초과가 발생해 완주하지 못했다.
