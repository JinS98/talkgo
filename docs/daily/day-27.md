## 구현 메모
- 변경한 파일: 웹 `TaskBoardPanel` 컴포넌트·SCSS, 두 사용자 브라우저 검증, README·데이터 모델·27일차 문서.
- 의사결정 및 이유: 이미 구현된 승인 시안의 3열 칸반과 서버 검증 버튼을 유지한다. 팀 전체·내 담당·내가 요청한 업무 범위와 제목 검색을 클라이언트에서 적용한다. 카드에 등록자·요청자·담당자·마감·예상 시간·검수 기간을 보여 주되 원본 채팅/DM 본문은 표시하지 않는다.
- 발견한 문제/해결: 한 상태 열만 선택해도 3열 그리드 너비가 적용되던 화면을 단일 열로 조정했다. 검색 라벨이 좁은 화면에서 줄바꿈되는 문제를 캡처로 확인해 정렬을 보완했다. 범위·검색 결과가 없을 때 안내를 표시한다.
- 다음 일차에 넘길 사항: 28일차 캘린더 기본에서 현재 업무·검수 일정 표시와 회의 일정 구분 요구를 비교한다. 드래그 상태 변경은 역할·상태별 서버 검증을 우회하지 않도록 추가하지 않았다.

## 포트폴리오 기록
- 문제 정의: 기존 보드는 워크스페이스 전체 업무를 상태별로 보여 주지만 내 담당·내 요청 업무를 골라 보거나 제목으로 찾기 어려웠다.
- 선택한 접근과 대안: 동일한 팀 공개 업무 구독 위에 개인 필터와 검색을 적용해 공유 데이터는 유지하고 화면만 다르게 표시했다. 상태 변경은 기존 명시적 액션과 서버 트랜잭션을 사용한다.
- 검증 근거(수치 임의 생성 금지): 두 Chrome 세션에서 같은 업무의 팀 공개, 요청자·담당자별 필터, 제목 검색, 요청 대기→수락·진행 열 이동, 기존 마감 협의·검수·알림 흐름을 확인했다. 웹 타입 검사·린트·빌드가 통과했다.
