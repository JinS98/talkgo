## 구현 메모
- 변경한 파일: `apps/web/src/features/tasks/calendarEvents.ts`, `TaskCalendarPanel.tsx`, `TaskCalendarPanel.module.scss`, 캘린더 검증 스크립트, `README.md`.
- 의사결정 및 이유: 팀 전체는 업무 기간·검수 기한·회의, 내 담당은 담당 업무 기간, 내가 검수할 업무는 요청자이면서 검수가 필요한 업무만 표시한다. 검수 요청 전에는 업무 기간, 검수 대기 중에는 제출일부터 검수 기한을 표시한다.
- 발견한 문제/해결: 기존 내 담당 필터에는 같은 업무의 검수 기한도 중복 표시됐다. 담당 업무 기간만 남기고 필터별 안내·빈 상태·로딩 및 오류 표시 범위를 정리했다.
- 다음 일차에 넘길 사항: 30일차 날짜 드래그에 따른 마감 변경 제안과 승인 후 확정.

## 포트폴리오 기록
- 문제 정의: 세 필터 버튼은 있었지만 검수와 담당 업무의 표시 범위가 겹쳐 의미가 불명확했다.
- 선택한 접근과 대안: 일정 변환 단계에서 사용자 ID와 필터 종류로 이벤트를 선택하고, 화면에 각 필터의 범위를 설명한다. 데이터 오류나 빈 상태도 선택한 범위에 맞춰 보여준다.
- 검증 근거(수치 임의 생성 금지): `npm run build:web`, `npm run lint`, `npm run test:calendar` 통과. Auth·Firestore·Functions 에뮬레이터와 Chrome의 `verify:calendar-browser`에서 방장·팀원의 세 필터 전환, 검수 대기 기간, 회의 제외, 빈 상태를 확인했다.
