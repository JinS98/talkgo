# 업무·검수 상태 정책

## 업무 요청
- REQUESTED → 담당자 수락 시 ACCEPTED → 담당자가 진행 시작 시 IN_PROGRESS.
- 담당자는 REQUESTED에서 거절할 수 있으며, REQUESTED·ACCEPTED·IN_PROGRESS에서 마감일 변경을 제안할 수 있다. 변경은 요청자가 승인해야 확정된다.
- 변경 승인 전 기존 확정 마감일과 업무 상태를 유지한다. 요청자가 변경을 거절하면 제안만 지운다.
- 요청 생성과 상태·마감 변경 이력은 업무 카드에서 확인한다.

## 검수
- 검수 미선택: 담당자 완료 → DONE.
- 검수 선택: 제출 → REVIEW_PENDING → 요청자 승인 DONE / 사유 포함 반려 REWORK.
- 22일차 구현: 담당자는 진행 중인 검수 대상 업무만 제출할 수 있다. 제출 시각과 검수 회차 1을 기록하고, 마감 변경 제안이 대기 중이면 제출을 막는다.
- 23일차 구현: 요청자만 검수를 승인하거나 2~1000자의 사유로 반려한다. 담당자는 반려 사유를 확인하고 재제출한다. 재제출은 검수 회차를 증가시키고 이전 반려 사유를 지운다. 검수 미선택 업무는 담당자가 진행 중에 바로 완료한다.
- REWORK 재제출 시 검수 회차 증가, 새 검수 기한 생성. 이전 예약 알림 무효화.
- 검수 기한까지 응답이 없으면 예약 작업이 자동 `DONE`으로 바꾸고 `completionReason=REVIEW_TIMEOUT`을 남긴다. 기한 경과 후에는 예약 작업 실행 전이라도 요청자의 승인·반려를 받지 않는다.

## 검수 기한

- 제출·재제출 시 서버가 `reviewSubmittedAt`부터 근무시간을 누적해 `reviewDeadlineAt`을 같은 트랜잭션에 저장한다. 이력에도 회차별 기한을 남기며 반려·승인 시 현재 기한을 비운다.
- Asia/Seoul 기준 월~금 09:00~12:00, 13:00~18:00, 공휴일·대체공휴일 제외.
- 1근무일 = 8근무시간.
- 예: 금 17시 제출 + 2근무일 → 화 17시(공휴일 없을 때).
- 예: 금 20시 제출 + 2근무일 → 화 18시(공휴일 없을 때).
- 대한민국 공휴일 규칙은 `date-holidays`의 KR 달력을 사용한다. 누락된 2026년 이후 노동절·대체공휴일과 2026년 6월 3일 지방선거일은 별도로 반영했다. 새 임시공휴일·선거일 또는 법령 변경 시 서버의 공휴일 규칙과 검증 사례를 갱신해야 한다.
- 공휴일 근거: [한국천문연구원 특일 정보 API](https://www.data.go.kr/data/15012690/openapi.do), [공휴일에 관한 법률](https://www.law.go.kr/lsInfoP.do?ancYnChk=0&lsId=014112), [2027년 월력요항 발표](https://www.kasa.go.kr/prog/plcyBrf/brief/kor/sub01_01_04/view.do?plcyBrfNo=431).
- 배포 환경에서는 `completeExpiredReviews`가 1분마다 기한이 지난 검수 업무를 조회한다. 로컬 `dev:all`에서는 같은 처리 함수를 1분마다 실행한다. 처리 시 현재 상태·검수 회차·제출 시각·기한을 다시 확인한다. `taskEvents`에 시스템 자동 완료 이력을 한 번만 남긴다.
- 자동 완료와 승인/반려 동시 실행 시 트랜잭션으로 단일 결과를 보장한다. 일시적 실행 실패는 다음 주기에 재시도한다.
- 제출 시 알림, 잔여 8/2근무시간 리마인드(중복 방지), 자동 완료 알림은 26일차 범위다.
