# 재사용 컴포넌트와 기능 관리

## 구분 기준

디자인과 기능을 서로 다른 저장소나 패키지로 나눌 필요는 없다. 웹 앱 안에서 **시각 요소**, **화면 동작**, **업무 기능**의 책임을 구분한다. 컴포넌트는 마크업·스타일·접근성·필요한 상호작용을 함께 보관하고, 여러 화면에서 같은 방식으로 쓰는 상태 관리나 브라우저 동작만 훅으로 분리한다. 서로 다른 화면이 비슷해 보인다는 이유만으로 색상이나 동작을 강제로 통일하지 않는다.

- `src/styles/global.scss`: 글꼴, 기본 스타일과 색상 CSS 변수. 새로운 공통 토큰은 실제로 여러 화면에 필요한 값일 때 추가한다.
- `src/components/`: 여러 기능에서 사용하는 범용 UI와 앱 레이아웃. 공통 UI를 만들면 해당 컴포넌트와 SCSS 모듈을 가까이 둔다.
- `src/hooks/`: 도메인에 종속되지 않는 재사용 가능한 React 동작. 구독 정리, 접근성, 포커스 동작 등 계약을 명시한다.
- `src/features/<기능>/`: 해당 업무의 컴포넌트, 훅, API와 스타일. 한 기능 안에서만 공유하는 요소도 여기에 둔다.
- `src/services/`, `src/store/`: 공통 외부 서비스 설정과 앱 전체에서 공유하는 상태. 단순한 화면 상태는 각 기능에 둔다.

## 현재 분리된 요소

| 요소 | 위치 | 책임과 사용처 |
| --- | --- | --- |
| 채팅 입력 | `features/chat/ChatComposer.tsx` | 미리보기와 실시간 채팅의 입력창, 전송 버튼, Enter 전송 및 Shift+Enter 줄바꿈. 초안·전송·연결 상태는 호출자가 관리한다. 글자 수 제한, 안내문, 입력 중 표시와 포커스 콜백을 각각 전달한다. 한글 조합 중 Enter는 전송하지 않는다. |
| 모달 동기화 | `hooks/useModalDialog.ts` | 열린 상태에 따라 네이티브 `dialog`의 `showModal()`과 `close()`를 동기화하고 정리한다. 캘린더의 회의 추가 및 마감 변경 모달에서 사용한다. 제목 연결, 취소·배경 클릭, 저장 중 닫기 방지는 호출자가 처리한다. |
| 워크스페이스 레이아웃 | `components/layout/WorkspaceLayout.tsx` | 사이드바와 콘텐츠 배치, 프로필 패널을 제공하는 앱 전용 레이아웃. 범용 디자인 시스템 컴포넌트는 아니다. |
| 프로필 패널 | `components/layout/MemberProfilePanel.tsx` | 워크스페이스 멤버 정보와 DM 진입을 표시하는 도메인 UI. |
| 업무 카드와 이력 | `features/tasks/TaskCard.tsx`, `features/tasks/TaskHistory.tsx` | 보드의 개별 업무 상태·응답과 이력 구독을 분리한다. 필터와 열 배치는 `TaskBoardPanel`이 관리하며, 두 컴포넌트는 기존 보드 스타일을 공유한다. |
| 워크스페이스 선택 | `features/workspace/WorkspacePicker.tsx` | 선택 메뉴의 열기·닫기와 바깥 클릭·Escape 처리를 관리한다. 실제 전환과 선택 데이터는 `WorkspaceGate`에서 전달한다. |
| 초대 현황 | `features/workspace/InviteList.tsx` | 초대 목록, 로딩·오류·철회 상태를 표시한다. 데이터 조회와 철회 요청은 `WorkspaceGate`에서 처리한다. |
| 업무 데이터 | `features/tasks/useWorkspaceTasks.ts` | 보드·캘린더 등에서 공유하는 업무 데이터 구독. Firebase와 업무 모델에 종속된다. |
| 채팅 이력 | `features/chat/useRoomHistory.ts` | 실시간 대화의 이전 메시지 로딩과 스크롤 처리. 채팅 기능에 둔다. |
| 캘린더 계산 | `features/tasks/calendarEvents.ts` | 업무·회의의 캘린더 이벤트 변환과 일정 계산. 화면 렌더링과 분리된 업무 로직이다. |

## 추가 분리 후보

| 후보 | 현재 위치 | 분리 전 확인할 점 |
| --- | --- | --- |
| 버튼과 입력 필드 | 인증, 워크스페이스, 업무별 SCSS 모듈 | 크기·상태·포커스·오류 표시가 실제로 같은지 디자인을 합의한 뒤 공통 UI로 추출한다. 현재는 시각적 차이와 기능별 상태가 있어 일괄 교체하지 않았다. |
| 상태·오류 안내 | 채팅, 인증, 업무 화면 | `alert`와 `status`, 재시도·닫기 동작이 다르다. 공통 형태와 접근성 계약이 정해지면 분리한다. |
| 팝오버 닫기 동작 | 알림 센터, 워크스페이스 선택, 날짜 선택 | 바깥 클릭, Escape, 포커스 복귀와 중첩 동작이 다르다. 공통 테스트를 갖춘 뒤 훅으로 추출한다. |
| 모달 외형 | 업무 생성 및 캘린더 모달 | 업무 생성은 날짜 팝오버와 저장 중 닫기 방지가 있다. 포커스·중첩·닫기 정책을 유지할 수 있을 때 공통 외형을 검토한다. |
| 아바타 | 계정 메뉴, 채팅, 멤버 목록·프로필 | 이름 표기와 클릭 가능 여부, 크기와 스타일이 다르다. 공통 규격이 생기면 표시 요소와 버튼의 접근성 이름을 함께 정의한다. |
| 필터 버튼 그룹 | 업무 보드와 캘린더 | 선택 상태와 스타일이 각 화면에서 다르다. 공통 디자인을 확정한 뒤 키보드 동작과 `aria-pressed`를 유지하며 추출한다. |

새 추상화는 최소 두 사용처에서 같은 역할과 동작이 확인될 때 도입한다. 공통화할 때는 기존 키보드·스크린리더 동작, 비활성화 조건, 오류 처리와 화면별 차이를 유지하고 관련 화면 검증을 실행한다.
