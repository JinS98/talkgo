# Taskgo (태스크고) — t:go

**대화가 업무가 되는 순간**

채팅을 업무로 전환하고 팀 전체의 업무·검수·캘린더를 공유하는 Slack 스타일 협업툴.

> **현재 상태: 28일차 팀 캘린더 구현(로컬 에뮬레이터 기준).** 채널·DM 메시지에서 업무를 요청하고, 담당자가 수락·진행 시작·마감 변경을 제안할 수 있습니다. 검수 대상 업무는 제출→요청자 승인 또는 사유 있는 반려→재제출 흐름을 지원하며, 기한이 지나면 자동 완료됩니다. 제출·잔여 8/2근무시간·완료 알림은 헤더의 알림 센터에 표시됩니다. 검수 없는 업무는 담당자가 완료합니다. FullCalendar에서 업무·검수·회의 일정을 실시간으로 확인하고 워크스페이스 멤버가 회의를 등록할 수 있습니다. 초대 메일의 실제 발송과 Functions·예약 작업 배포는 SMTP·Blaze 설정 전입니다.

## 기술 구성
- Web: React + TypeScript + Vite + SCSS Modules + Zustand
- 실시간 채팅: Node.js + Socket.io (Cloud Run 예정)
- 인증/DB: Firebase Auth + Cloud Firestore
- 서버 로직: Cloud Functions (워크스페이스·초대·업무 생성·요청 응답·검수 기한 예약 작업)
- 개발: Firebase Emulator Suite, 로컬 Socket.io

## 실행

```bash
npm install
npm run dev:all
```

`npm run dev:all`은 Firebase 에뮬레이터·채팅 서버·웹 개발 서버를 한 터미널에서 시작하고 접속 주소를 출력합니다. 기존 웹 서버가 5173 포트를 사용 중이면 다음 빈 포트를 선택합니다. Ctrl+C로 함께 종료합니다. 이 명령은 실제 Firebase 데이터와 분리된 `demo-taskgo` 프로젝트를 사용하므로 새 계정과 워크스페이스를 만들어 확인하세요. Node.js 22.13+와 Java 21 이상이 필요합니다. 시작 스크립트는 설치된 JDK 21 이상을 찾아 Firebase 에뮬레이터에 사용하므로 시스템 기본 Java가 17이어도 실행할 수 있습니다. 로그인 후 처음 한 번 이름을 정합니다. 기존 이름 없는 계정은 임시 이름이 제안되며 계정 메뉴에서 수정할 수 있습니다. 워크스페이스가 없어도 즉시 만들 필요는 없습니다. 초대 메일의 링크를 열거나 시작 화면에 붙여 넣어 참여할 수 있습니다. 워크스페이스를 만들면 장 권한이 부여됩니다. 장에게만 보이는 사이드바의 **워크스페이스 관리**에서 멤버와 초대 현황을 확인하고 초대받을 사람의 이메일 주소로 초대할 수 있습니다. 초대 링크는 로컬에서는 함수 로그와 관리 화면에 표시됩니다. 초대받은 주소로 로그인한 사용자가 링크에서 **초대 수락**을 눌러 가입합니다.

채팅 서버 코드를 변경한 뒤에는 `npm run dev:all`을 재시작해야 새 인증 정책이 적용됩니다. 실행 중인 에뮬레이터의 계정·채팅을 보존하려면 별도 터미널에서 `npm run save:emulator`를 먼저 실행하세요. 재시작하면 저장된 `.taskgo-emulator-data`를 자동으로 불러옵니다. 이 폴더는 Git에 포함되지 않습니다.

로그인한 워크스페이스의 채팅에서는 기본 `전체` 채널로 입장하며, 처음 입장할 때 서버가 멤버십을 확인하고 채널을 만듭니다. Enter로 전송하고 Shift+Enter로 줄을 바꿉니다. 새 메시지는 같은 룸의 다른 브라우저에 바로 표시됩니다. 저장된 메시지의 **업무 요청**을 누르면 원문을 참고하며 제목·담당자·마감·설명·예상 시간·검수를 편집하고 최종 저장할 수 있습니다. 모달의 **초안 제안받기**를 직접 누르면 서버가 접근 권한을 확인하고 같은 대화의 선택 메시지까지 최대 8개를 사용합니다. OpenAI API 키가 설정되면 이 문맥을 전송해 AI 후보를 받고, 로컬 에뮬레이터에 키가 없으면 외부 전송 없이 문장 기반 초안을 보여줍니다. 로컬 초안은 AI 생성 결과가 아님을 표시합니다. 후보를 선택해도 업무가 저장되지는 않으며 제목을 수정한 뒤 **요청하기**를 눌러야 확정됩니다. 제목·설명과 업무 메타데이터는 팀 전체에 공개되며 DM 원문은 업무에 복사되지 않습니다. 같은 채널·DM에 있는 팀원이 입력하면 작성 중 표시가 나타나고 입력을 멈추거나 대화방을 떠나면 사라집니다. 과거 대화는 최근 30개부터 표시하고 상단의 **이전 대화 불러오기**로 계속 확인할 수 있습니다. 오프라인에서는 전송을 막고 초안은 유지합니다. 온라인 복귀 후 다시 인증·룸 참가를 거쳐 서버의 저장 내역을 읽고 누락분을 채웁니다. 연결·전송 오류를 구분해 표시하고 전송 실패한 메시지는 옆의 **다시 시도**로 재전송할 수 있습니다. 현재 탭의 메시지·초안은 로그아웃하면 지워집니다. DM은 기존에 생성된 룸만 목록에 나타납니다. 독립 미리보기의 샘플 채팅은 `npm run test:chat`으로 확인합니다.

업무 등록 시 요청자는 생성자가 기본값이며 다른 멤버로 바꿀 수 있습니다. 실제 생성자는 별도로 기록합니다. 본인을 담당자로 지정하면 업무가 즉시 수락되고, 검수는 `선택 안 함` 또는 1~10근무일 중 고릅니다. 모달 바깥을 클릭하거나 Escape를 누르면 저장 없이 닫힙니다.

상단의 **Chat · Board · Calendar** 탭에서 화면을 전환합니다. Board는 워크스페이스 업무를 요청 대기·수락/진행·완료/거절 열로 실시간 표시합니다. 담당자는 `REQUESTED` 업무를 수락·거절하고, 수락한 업무의 **진행 시작**을 누를 수 있습니다. 요청·수락·진행 중에도 새 마감을 제안할 수 있으며 요청자가 승인·거절합니다. 승인 전 기존 마감과 업무 상태는 유지됩니다. 검수를 선택한 업무는 진행 중에 **검수 요청**으로 제출하고, 요청자는 **검수 승인** 또는 사유를 적어 **반려**할 수 있습니다. 반려된 업무는 담당자가 **재제출**하며 검수 회차가 증가합니다. 검수가 없는 업무는 **완료하기**로 마칩니다. 각 카드의 **이력 보기**에서 상태·마감·검수 변경을 확인할 수 있습니다. 제출·재제출 시 서울 기준 근무시간과 공휴일을 적용한 검수 기한이 저장되고 보드에 표시됩니다. Calendar는 FullCalendar 월간 화면에 업무 생성일부터 마감일까지 표시합니다. 팀 전체·내 담당·내가 요청한 검수 필요 업무를 필터링하며 요청 대기는 점선, 확정 업무는 단색으로 구분합니다. **내가 검수할 업무** 필터에서 검수 대기 업무는 제출일부터 검수 기한까지 표시합니다. **회의 추가**에서 멤버가 제목과 시작·종료 시각을 입력하면 팀 전체 일정에 표시됩니다. 일정이 많은 날짜는 더보기에서 모두 볼 수 있습니다. [UI/UX 시안](docs/design/README.md)의 밝은 테마를 앱에 적용했습니다.

Calendar의 업무 바는 생성일부터 마감일까지 이어집니다. 한 날짜에 일정이 세 개를 넘으면 `더보기`에서 그날의 업무 전체를 확인할 수 있습니다. 날짜는 한국 시간 기준입니다.

캘린더의 **팀 전체 일정**은 업무·검수 기한·회의를, **내 담당 업무**는 본인이 담당자인 업무 기간만 보여줍니다. **내가 검수할 업무**는 본인이 요청자이고 검수를 선택한 업무를 보여주며, 검수 요청 전에는 업무 기간을, 검수 대기 중에는 제출일부터 검수 기한까지 표시합니다. 일정이 없는 범위에는 빈 상태 안내가 나타납니다.

담당자는 캘린더에서 요청·수락·진행 중인 업무 바를 옮기거나 끝을 드래그해 새 마감 날짜를 제안할 수 있습니다. 드래그 직후 업무 바는 원래 위치로 돌아가며, 확인 창에서 **제안 보내기**를 눌러야 요청자에게 전달됩니다. 요청자는 캘린더의 **받은 마감 변경 제안**에서 승인·거절합니다. 승인 전에는 기존 마감일이 유지됩니다. 검수·회의 일정과 이미 제안 대기 중인 업무는 드래그할 수 없습니다.

업무 보드는 워크스페이스의 공개 업무를 요청 대기·수락/진행·완료/거절 열에 표시합니다. **팀 전체**, **내 담당 업무**, **내가 요청한 업무**로 범위를 바꾸고 제목으로 검색할 수 있습니다. 필터는 화면 표시만 바꾸며 팀 공개 업무 자체를 변경하지 않습니다. 카드에는 등록자·요청자·담당자·마감 정보가 표시되고 원본 채팅/DM 본문은 포함되지 않습니다. 상태 변경은 권한에 따라 보이는 카드 버튼에서 처리합니다.

채팅 메시지의 **업무 보기**로 연결된 업무 카드를 열 수 있고, 카드의 **원본 대화 보기**로 해당 메시지에 돌아갈 수 있습니다. 원본이 DM이면 현재 참여자만 열 수 있습니다. 다른 워크스페이스 멤버에게는 업무 자체만 보이며 원본 메시지나 DM 대화 정보는 표시되지 않습니다.

채팅·보드·캘린더는 워크스페이스 업무 목록 구독을 공유해 화면을 바꿀 때 같은 목록을 다시 구독하지 않습니다. 업무와 원본 메시지로 이동하면 대상에 키보드 포커스가 옮겨집니다. [33일차 UX·성능 기록](docs/daily/day-33.md)에 작은 화면과 브라우저 검증 결과를 정리했습니다.
캘린더 코드는 캘린더 화면을 열 때 내려받으며, 그동안 로딩 안내를 표시합니다.

`npm run test:task-links`는 Auth·Firestore 에뮬레이터와 Chrome에서 채널·DM 왕복 이동, 오래된 메시지로 이동, DM 비참여자의 원본 접근 차단을 확인합니다. 실행 전 `dev:all`을 종료하고 Java 21 이상을 사용하세요.

보안·통합 검증은 `npm run test:workspace`, `npm run test:socket`, `npm run test:task-model`, `npm run test:task-links`를 순서대로 실행합니다. 초대 링크·멤버십·Firestore 규칙·소켓 룸·업무 경합의 점검 항목과 로컬 결과는 [32일차 검증 체크리스트](docs/daily/day-32.md)에 기록했습니다. 각 명령은 기본 에뮬레이터 포트를 사용하므로 실행 중인 `dev:all`을 먼저 종료하세요.

Auth·Firestore 에뮬레이터를 실행한 뒤 `npm run dev:socket:emulator`로 소켓 서버를 별도 실행합니다. `http://127.0.0.1:3001/healthz`에서 상태를 확인할 수 있습니다. `npm run test:socket`은 서버 권한·저장·타이핑 전파를, `npm run test:live-chat`은 Auth·Firestore·Functions 에뮬레이터와 두 Chrome 세션으로 채널·DM 업무 요청, 진행 시작·마감 협의·이력, 웹 송수신·과거 내역·오프라인 복구를 검증합니다. 두 테스트는 기존 에뮬레이터·소켓 서버를 종료한 상태에서 실행하세요. 설정과 이벤트 설명은 [소켓 서버 문서](apps/socket-server/README.md)를 참고하세요.

`npm run test:task-model`은 별도 Auth·Firestore·Functions 에뮬레이터에서 업무 스키마·권한·DM 원문 보호, 요청·진행 상태 전이와 이력 접근 권한을 확인합니다. 기본 포트를 사용하므로 `npm run dev:all`을 종료한 뒤 실행하세요. 요청 필드와 상태 정책은 [데이터 모델](docs/03-data-model.md)에 정리했습니다.

`npm run test:review-deadline`은 에뮬레이터 없이 서울 근무시간·공휴일·대체공휴일을 적용한 검수 기한 계산을 확인합니다. 공식 임시공휴일이나 선거일이 새로 지정되면 [검수 정책](docs/05-task-review-policy.md)의 공휴일 데이터를 갱신해야 합니다.

`npm run test:review-timeout`은 Firestore 에뮬레이터에서 기한 초과·중복 실행·검수 회차·승인/반려 경합을 확인합니다. 기본 에뮬레이터 포트를 사용하므로 `dev:all`을 종료한 뒤 실행하세요. `npm run dev:all`에는 검수 기한 자동 완료 반복 실행기가 포함되며 약 1분마다 기한을 확인합니다. 배포 환경의 `completeExpiredReviews` 예약 함수도 1분마다 실행됩니다. Cloud Scheduler를 사용하려면 Firebase 프로젝트의 요금제와 함수 배포 설정이 필요합니다. 실제 프로젝트에는 아직 배포하지 않았습니다.

`npm run test:review-notifications`는 제출·8/2근무시간 리마인드·완료 알림, 중복 방지와 본인 읽기 권한을 Firestore 에뮬레이터에서 확인합니다. 알림은 앱 내부에만 기록되며 이메일이나 브라우저 푸시는 보내지 않습니다. 헤더의 **알림** 버튼에서 최근 50개를 보고 선택하면 읽음 처리 후 업무 보드로 이동합니다.

## Firebase 개발 환경

실제 Firebase 프로젝트는 `taskgo-jins98`, 웹 앱은 `taskgo-web`입니다. 이메일·비밀번호와 Google 로그인 공급자를 활성화했고, Cloud Firestore 기본 데이터베이스는 서울(`asia-northeast3`)에 생성했습니다. [Firestore 규칙](firestore.rules)은 로그인한 이메일 사용자의 워크스페이스·장 멤버십·본인 목록을 일괄 생성할 때만 클라이언트 쓰기를 허용합니다. 초대·채팅·업무 쓰기는 계속 차단합니다. 실제 프로젝트에는 변경된 규칙을 별도로 배포해야 하며 초대용 Functions는 아직 배포하지 않았습니다.

로컬 에뮬레이터는 Java 21이 필요합니다. 터미널 두 개에서 실행합니다.

```bash
npm run emulators
npm run dev:web:emulator
```

인증 에뮬레이터는 `127.0.0.1:9099`, Firestore는 `127.0.0.1:8080`, Functions는 `127.0.0.1:5001`, 에뮬레이터 UI는 `127.0.0.1:4000`을 사용합니다. 웹 앱의 `emulator` 모드는 [가상 프로젝트 설정](apps/web/.env.emulator)을 사용하므로 실제 Firebase 프로젝트에 접속하지 않습니다. Google 로그인 버튼은 에뮬레이터의 가상 계정 선택 창을 엽니다.

로그인한 계정의 **계정** 메뉴에는 표시 이름과 이메일이 보이며 이름을 수정할 수 있습니다. 채팅·DM·업무의 이름 표시는 워크스페이스 멤버 이름과 함께 갱신됩니다. 이메일 계정에는 Google 로그인을 연결할 수 있습니다. 이미 다른 계정에 연결된 로그인 방식은 자동 병합하지 않고 오류를 표시합니다.

실제 프로젝트 설정으로 `npm run dev:web`을 실행할 때는 변경된 Firestore 규칙을 배포해야 이름 등록과 새 이메일 계정의 워크스페이스 만들기가 동작합니다. 초대 메일 보내기는 Functions와 SMTP 설정 전까지 사용할 수 없으며, 워크스페이스를 만든 직후 자동으로 초대가 발송되지는 않습니다.

실제 프로젝트 웹 설정은 [환경 변수 예시](apps/web/.env.example)를 `apps/web/.env.local`로 복사해 입력합니다. 이 PC에는 웹 앱 설정이 입력되어 있습니다. `VITE_USE_FIREBASE_EMULATORS=false`일 때만 실제 프로젝트를 사용하며 `.env.local`은 Git에서 제외됩니다.

인증 공급자 설정을 다시 배포하려면 [예시 설정](firebase.auth.example.json)을 `firebase.auth.local.json`으로 복사하고 Google OAuth 지원 이메일을 입력한 뒤 다음 명령을 사용합니다. 로컬 설정 파일은 Git에서 제외됩니다.

```bash
npx firebase deploy --only auth --config firebase.auth.local.json --project taskgo-jins98
```

## 폴더 구조

| 경로 | 역할 |
|---|---|
| `apps/web/src/features/` | 인증·워크스페이스·채팅·업무·캘린더별 화면과 로직 |
| `apps/web/src/components/`, `hooks/` | 도메인에 묶이지 않는 UI와 재사용 훅 |
| `apps/web/src/services/`, `store/` | Firebase 연결과 클라이언트 상태 관리 |
| `apps/web/src/types/`, `config/` | 웹 앱 공통 타입과 환경 설정 |
| `shared/contracts/` | 웹·소켓 서버 간 이벤트 계약 |
| `apps/socket-server/` | 채팅 서버의 연결·인증·룸 권한 검사·메시지 저장과 전파 |
| `functions/` | 워크스페이스·초대 서버 함수와 SMTP 배포 설정 안내 |

## 환경 변수

웹 앱의 예시는 `apps/web/.env.example`에 있습니다. 실제 프로젝트를 사용할 때 웹 설정을 `apps/web/.env.local`에 입력합니다. `.env.local`은 Git에서 제외됩니다.

`VITE_` 변수는 브라우저 번들에 공개되므로 서버 비밀키를 넣지 않습니다. 웹 설정의 소켓 주소 기본값은 `http://127.0.0.1:3001`이며 `VITE_SOCKET_URL`로 변경할 수 있습니다. 소켓 서버는 `FIREBASE_PROJECT_ID`와 Firebase Admin 자격 증명을 서버 환경에서 읽습니다.

초기 설정 검증:

```bash
npm run typecheck
npm run lint
npm run build:web
npm run build:functions
npm run build:socket
npm run test:socket
npm run test:live-chat
npm run test:ui
npm run test:firebase
npm run test:auth
npm run test:workspace
```

## 중요한 원칙
- 메시지는 **Socket.io 서버를 통해서만 저장**하고 Firestore 직접 쓰기를 허용하지 않습니다.
- 업무·캘린더 실시간 동기화는 Firestore `onSnapshot`을 사용합니다.
- DM 원문은 참여자만 볼 수 있지만, 업무 공개 메타데이터는 팀에서 볼 수 있습니다.
- AI는 사용자가 **초안 제안받기**를 누를 때만 호출합니다. 로컬 에뮬레이터는 키가 없으면 문장 기반 초안을 대신 표시합니다.
- Cloud Run 무료 할당량을 목표로 하되 **무료 청구는 보장하지 않습니다**.
